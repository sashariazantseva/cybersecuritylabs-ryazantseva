# ЛР4. Особистий цифровий підпис

**Автор:** Рязанцева Олександра Сергіївна, гр. 6.04.122.010.23.3

Спрощена система цифрових підписів на основі RSA-2048. Ключі генеруються
з персональних даних (ПІБ, дата народження) і секретного слова.

## Як це працює

1. `seed = SHA-256(ПІБ | дата | секретне слово)`
2. із seed генеруються прості числа p і q (по 1024 біти, тест Міллера-Рабіна)
3. публічний ключ `(n = p·q, e = 65537)`, приватний ключ `d = e⁻¹ mod (p-1)(q-1)`
4. підпис `s = H^d mod n`, де H - хеш документа
5. перевірка `s^e mod n == H`

Підтримуються хеш-функції SHA-256, SHA-512, SHA3-256 і BLAKE2b.

## Вкладки програми

| Вкладка | Що робить |
|---|---|
| 1 · Ключі | генерація пари ключів і збереження у `keys/` |
| 2 · Підписати | хеш документа і підпис → файл `.sig` |
| 3 · Перевірити | перевірка підпису публічним ключем: ДІЙСНИЙ / ПІДРОБЛЕНИЙ |
| 4 · Тест підробки | змінений документ, змінений підпис, чужий ключ, чужий документ, вигаданий підпис |
| 5 · Хеш і підпис | лавинний ефект хешу і різниця між хешуванням і підписуванням |

## Запуск

```bash
python app.py                           # програма з вікном (потрібен тільки Python)
python demo.py                          # усе без вікна, секретне слово вводиться з клавіатури
python -m unittest -v test_signature.py # 11 тестів
```

## Файли

```
signature.py      генерація ключів, підпис, перевірка
forgery.py        сценарії підробки
app.py, demo.py   програма з вікном і без
documents/        резюме, звіт з ЛР3, їх підписи (.sig) і «підроблена» копія резюме для тесту
keys/             public_key.json (приватний ключ у репозиторій не додано)
results/          підписи різними хеш-функціями, файли тестів підробки, demo.json
screenshots/      скриншоти програми і Kleopatra (Gpg4win)
```

Приватний ключ і секретне слово навмисно не зберігаються в репозиторії:
хто знає приватний ключ, той може підписувати документи від імені власника.
